# Secure Multi-User Mobile Payment Simulation System Using Python and MySQL

## 1) Project Overview
This project is a Class 12 Computer Science submission that simulates a secure mobile payment platform using:
- **Frontend:** Tkinter GUI
- **Backend:** Python
- **Database:** MySQL
- **Connector:** `mysql-connector-python`
- **Receipt Engine:** `reportlab.platypus`

It supports registration, login, balance view, wallet-to-wallet transfer, PDF receipt generation, and polling-based transaction notifications.

## 6) Architecture Explanation
### A. Presentation Layer
- Tkinter forms for:
  - Login
  - Registration
  - Dashboard
  - Transfer
  - Transaction history

### B. Business Logic Layer
- Validates credentials and input.
- Performs secure wallet transfer checks:
  - Receiver exists
  - Sufficient balance
  - Transaction cap = ₹99999
- Controls polling notifications.
- Generates receipt PDF after successful transactions.

### C. Data Layer
- Uses `mysql-connector-python` for all DB operations.
- Uses two core tables:
  - `users`
  - `transactions`
- Uses SQL transactions (`start_transaction`, `commit`, `rollback`) for atomic updates.

## 7) Working Flow Explanation
1. **User Registration**
   - User enters name, username, password, initial balance.
   - Password is hashed with SHA-256.
   - `wallet_uid` generated by `uuid.uuid4().hex`.
   - `bank_uid` generated by custom format `BANK-########`.
   - User is inserted into `users` table.

2. **User Login**
   - Username + password entered.
   - Password hashed again and matched with stored hash.
   - On success, dashboard opens.

3. **Dashboard**
   - Shows wallet UID and current balance.
   - Shows all transactions from last 30 minutes.

4. **Money Transfer**
   - Sender enters receiver wallet UID and amount.
   - System validates amount, limit, receiver existence, and balance.
   - DB transaction begins.
   - Sender debited and receiver credited atomically.
   - Transaction record inserted with generated `txn_id`.
   - Changes committed, else rollback.

5. **Receipt Generation**
   - PDF generated as `receipt_<txn_id>.pdf` using `reportlab.platypus`.

6. **Notification Polling**
   - Every 5 seconds, app checks incoming transactions from last 30 minutes.
   - If a new transaction is found, Tkinter popup is shown.

## 8) UUID Explanation (Why and Advantages)
### What is UUID?
UUID (Universally Unique Identifier) is a value designed to be globally unique.

### In this project:
- `wallet_uid = uuid.uuid4().hex`
- `txn_id = "TXN-" + uuid.uuid4().hex`
- `bank_uid = "BANK-" + random 8 digits`

### Why used?
- Prevents predictable IDs unlike simple sequential numbers.
- Makes IDs unique across devices/instances.
- Better for distributed/multi-user systems.
- Improves security by reducing ID guessability.

### Advantages
1. High uniqueness
2. Better privacy/security
3. Supports scaling
4. Useful for logs and tracking
5. Safer in concurrent multi-user environment

## 9) Viva Questions with Answers (15)
1. **Q:** Why is SHA-256 used in this project?
   **A:** To securely hash passwords so plaintext passwords are never stored.

2. **Q:** Why not store normal passwords?
   **A:** Plaintext passwords are insecure and can be stolen directly if DB is leaked.

3. **Q:** What is atomicity in database transactions?
   **A:** Either all operations succeed together or all fail together (rollback).

4. **Q:** Why is `start_transaction()` used?
   **A:** To ensure debit, credit, and transaction insert happen as one atomic unit.

5. **Q:** What is the role of `commit()`?
   **A:** It permanently saves successful changes in the database.

6. **Q:** What is the role of `rollback()`?
   **A:** It cancels incomplete or failed operations to keep data consistent.

7. **Q:** Why use UUID for transaction ID?
   **A:** To create highly unique non-sequential IDs for secure tracking.

8. **Q:** What is polling in this project?
   **A:** Repeatedly checking DB at fixed intervals for new incoming payments.

9. **Q:** Why use Tkinter for this project?
   **A:** It is built-in, easy for CBSE level GUI development, and lightweight.

10. **Q:** Why use foreign keys in transactions table?
    **A:** To ensure sender and receiver UIDs always refer to valid users.

11. **Q:** How is transaction limit enforced?
    **A:** By validating amount in Python before processing transfer.

12. **Q:** How are two app instances synchronized?
    **A:** Both read/write from the same MySQL DB; refresh/polling fetches latest data.

13. **Q:** Which library creates receipts?
    **A:** ReportLab using `reportlab.platypus` classes.

14. **Q:** Why not use auto-increment for txn_id?
    **A:** Requirement demands UUID-based IDs and it is less predictable than integers.

15. **Q:** What SQL query shows last 30-minute transactions?
    **A:** `SELECT * FROM transactions WHERE date_time >= NOW() - INTERVAL 30 MINUTE;`
